## Reverse Proxy
```
Serveur placé devant les serveurs web qui dirige les requêtes des clients vers les serveurs appropriés (ex: Nginx).
```

## Time-to-Market
```
Temps écoulé entre la conception d'une idée et sa mise à disposition sur le marché pour les utilisateurs.
```

## Certification HDS 
```
Certification réglementaire pour les hébergeurs de données de santé.
```

## RTO (Recovery Time Objective)
```
Durée maximale acceptable pendant laquelle un service peut rester interrompu après un incident.
```

## PRA (Plan de Reprise d'Activité)
```
Ensemble de procédures permettant de reconstruire un système après un sinistre majeur (focus sur la technique).
```

## Secrets
```
Objets sensibles (mots de passe, clés API) stockés de manière sécurisée et injectés au moment de l'exécution.
```

## Réplication de données
```
Processus de copie des données sur plusieurs nœuds pour garantir qu'elles restent accessibles si un serveur tombe en panne.
```

## Code Review (Revue de code)
```
Processus où un développeur examine le code d'un collègue pour détecter des bugs ou des failles avant l'intégration.
```

## Sharding
```
Méthode de partitionnement des données qui distribue des morceaux d'une base de données sur plusieurs serveurs pour améliorer les performances.
```

## Staging (Pré-production)
```
Environnement miroir de la production où l'on teste l'application dans des conditions réelles avant le déploiement final.
```

## NoSQL
```
Type de base de données (comme MongoDB) conçu pour gérer des données non structurées et offrir une grande flexibilité de schéma.
```

## Latence
```
Temps nécessaire pour qu'une donnée voyage de l'émetteur au récepteur.
```

## Caching (Mise en cache)
```
Stockage temporaire de données fréquemment accédées pour accélérer les réponses futures.
```

## Least Privilege (Moindre privilège)
```
Principe de sécurité consistant à ne donner qu'un accès minimal strictement nécessaire à un utilisateur ou un service.
```

## Linter
```
Outil d'analyse statique qui vérifie que le code respecte les standards de qualité et ne contient pas d'erreurs de syntaxe évidentes.
```

## Conteneurisation (Docker)
```
Méthode d'empaquetage d'une application avec toutes ses dépendances pour garantir son fonctionnement identique partout.
```

## Load Balancing
```
Technique de répartition de la charge réseau sur plusieurs serveurs pour éviter la saturation d'un seul point.
```

## SaaS (Software as a Service)
```
Modèle de distribution de logiciel où l'application est hébergée dans le Cloud et accessible via internet.
```

## Unit Testing (Tests unitaires)
```
Tests automatisés vérifiant le bon fonctionnement d'une petite portion précise de code (une fonction, par exemple).
```

## Merge Request / Pull Request
```
Demande de fusion de modifications de code dans la branche principale, servant de support à la revue de code.
```

## Graceful Shutdown
```
Capacité d'une application à finir ses tâches en cours avant de s'éteindre suite à un signal d'arrêt.
```

## RPO (Recovery Point Objective)
```
Quantité maximale de données que l'entreprise accepte de perdre (ex: 1 heure de données).
```

## Try-Catch-Finally
```
Bloc de code permettant de tenter une action, de capturer une erreur si elle survient, et d'exécuter un code de nettoyage quoi qu'il arrive.
```

## DNS (Domain Name System)
```
Système traduisant les noms de domaine (ex: mon-app.com) en adresses IP compréhensibles par les machines.
```

## SRE (Site Reliability Engineering)
```
Discipline appliquant les principes de l'ingénierie logicielle aux problèmes d'exploitation et de fiabilité.
```

## Scalabilité (Élasticité)
```
Capacité d'un système à s'adapter à la charge en ajoutant ou supprimant des ressources automatiquement.
```

## Self-Healing (Auto-guérison)
```
Capacité d'une infrastructure (comme Kubernetes) à détecter un conteneur défaillant et à le redémarrer automatiquement.
```

## SLA (Service Level Agreement)
```
Contrat définissant le niveau de service attendu (ex: 99,9% de disponibilité) entre un fournisseur et son client.
```

## PCA (Plan de Continuité d'Activité)
```
Stratégie globale pour maintenir les services métiers essentiels sans interruption, même pendant un incident.
```

## Pipeline CI/CD
```
Suite d'étapes automatisées (build, test, deploy) que le code doit traverser pour arriver en production.
```

## Post-mortem
```
Analyse écrite d'un incident majeur visant à comprendre les causes profondes et à définir des actions correctives.
```

## Vendor Lock-in
```
Risque de devenir dépendant d'un seul fournisseur Cloud à cause de l'utilisation de technologies propriétaires.
```
