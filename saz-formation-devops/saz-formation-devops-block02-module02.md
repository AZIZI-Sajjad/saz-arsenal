## Test d'intégration
```
Test de plus haut niveau que le test unitaire. Son objectif est de vérifier l'opérationnalité entre 2 zones de codes (comme 2 classes) ou bien 2 composants logiciels.
```

## Spring Framework
```
Framework Java permettant de le développement d'application complexe. Ce framework est un cadre performant pour des applications maintenables, robustes et évolutives.
```

## Cucumber
```
Framework de test Java (mais également disponible dans d'autres langages). Il permet la mise en œuvre de l'approche Behavior Driven Development en définissant des scénarios de tests selon le formalisme Gherkin.
```

## Workflow Git
```
Ensemble de règles d'utilisation de Git pour unifier les différents collaborateurs à un projet.
```

## CD
```
CD est l'acronyme pour Continuous Deployment/Delivery, en français livraison/déploiement continue. Cela correspond à la mise en oeuvre de process automatisés pour la mise en production d'une solution applicative.
```

## Gherkin
```
Formalisme utilisé dans les tests réalisés selon l'approche Behavior Driven Development. La structure d'un scénario Gherkin est la suivante : Etant donné que ... lorsque ... alors ...
```

## Spring Boot
```
Module de Spring Framework facilitant la mise en œuvre d'un projet Spring et de ses composants. Certains de ses avantages sont les starters de dépendances, l'auto configuration, la gestion des propriétés.
```

## CLI
```
Acronyme pour Command Line Interface. C'est une interface permettant l'exécution de commande.
```

## Heroku
```
Plateforme cloud d'hébergement de solutions applicatives. Réputée pour sa simplicité d'utilisation par des développeurs. La plateforme s'appuie sur l'utilisation de repository Git pour le déploiement du code source de l'application.
```

## Mockito
```
Framework de test Java permettant de simuler des objets via une élément nommé Mock. Il permet ainsi de rendre indépendant un code de son contexte de réaliser des tests unitaires performants.
```

## Test fonctionnel
```
Test de haut niveau pour vérifier le comportement d'une fonctionnalité de A à Z.
```

## Environnement de pré production
```
Ensemble des systèmes et logiciels nécessaires au test d'une application dans une situation identique à celle de production, c'est à dire dans une situation identique à celle où les utilisateurs finaux vont utiliser l'application.
```

## Environnement de développement
```
Ensemble des systèmes et logiciels nécessaires au développement d'une application.
```

## CI
```
CI est l'acronyme pour Continuous Integration, en français l'intégration continue. Cela correspond à la mise en place de process automatisé pour la construction, le test et la production de solutions applicatives.
```

## Environnement de tests
```
Ensemble des systèmes et logiciels nécessaires au test d'une application. Cette environnement doit satisfaire aux exigences minimales pour exécuter l'application développée.
```

## GitHuB
```
Plateforme cloud pour l'hébergement de repository Git.
```

## BDD
```
Acronyme pour Behavior Driven Development. Méthode de tests issue des principes Agile qui a pour objectif de définir les scénarios de test en mettant l'utilisateur au centre de ces derniers.
```

## H2
```
Base de données relationnelle "InMemory". Elle n'existe que lorsque l'application associé est en cours d'exécution.
```

## Git
```
Outil de gestion de version. Il permet de versionner un projet de développement informatique. Parmi les fonctionnalités les plus caractéristiques il y a l'historique de commit, la gestion de branches et la synchronisation avec des dépôts distants.
```

## JUnit
```
Framework de test JAVA permettant l'implémentation de différents types de tests.
```

## Spring Web
```
Module de Spring permettant le traitement de requête HTTP. Il est un élément clé de toutes applications web réalisés avec Spring.
```

## Pyramide des tests
```
Représentation hiérarchique des différents types de tests en fonction de leur nature. Un test de nature technique sera bas niveau et donc au bas de la pyramide. Un test de nature fonctionnelle sera haut niveau et donc en haut de la pyramide.
```

## GitHub Actions
```
Fonctionnalité disponible sur un repository GitHub pour mettre en œuvre une chaîne de build CI/CD.
```

## Spring Data JPA
```
Module de Spring permettant l'interaction avec une base de données relationnelle.
```

## GitFlow 
```
Workflow Git reposant sur l'utilisation de nombreux types de branches pour structurer le développement.
```

## Java
```
Langage de programmation dont certaines caractéristiques principalement sont l'utilisation du paradigme objet, le typage et la compilation.
```

## Gestion de projet
```
Discipline visant à organiser, planifier, suivre et contrôle un projet de développement informatique. Cette discipline peut s'appliquer à d'autres domaines métiers.
```

## Environnement de production 
```
Ensemble des systèmes et logiciels nécessaires à l'exécution d'une application pour que les utilisateurs finaux puissent l'exploiter tel qu'attendu.
```

## DevOps
```
Démarche pour unifier l'univers du développement et de l'administration dans le but de booster la productivité. Cette démarche tend vers l'automatisation des étapes du cycle de vie du code notamment à travers la mise en œuvre d'une chaîne de build.
```

## Tests unitaires
```
Test de bas de niveau qui s'attelle à la vérification d'un périmètre précis de code.
```
