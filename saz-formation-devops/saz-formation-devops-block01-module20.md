## Limite de WIP
```
Nombre maximal d’éléments autorisés simultanément dans une étape du flux afin de réduire la surcharge, le multitâche et les délais.
```

## Scrum
```
Framework agile léger fondé sur l’empirisme, qui organise le travail en Sprints autour de la transparence, de l’inspection et de l’adaptation.
```

## Sprint Review
```
Événement de fin de Sprint consacré à l’inspection de l’incrément, des résultats et du contexte afin d’adapter les prochaines orientations.
```

## Sprint
```
Période de durée fixe, d’un mois ou moins, pendant laquelle la Scrum Team poursuit un objectif et produit un incrément utilisable.
```

## Incrément
```
Version utilisable du produit qui intègre le travail terminé pendant le Sprint et respecte la Definition of Done.
```

## Valeur
```
Bénéfice réel produit pour l’utilisateur ou l’organisation, mesuré par l’usage, l’impact métier, économique ou stratégique plutôt que par le volume livré.
```

## Auto-organisation
```
Capacité d’une équipe à décider collectivement comment atteindre un objectif, répartir le travail et s’adapter dans un cadre clairement défini.
```

## Objectif de Sprint
```
Résultat utile que la Scrum Team cherche à atteindre pendant un Sprint et qui guide ses choix, ses arbitrages et ses adaptations.
```

## Incertitude
```
Part de ce qui reste inconnu ou instable dans un projet : besoins, solution, usages, contraintes ou réactions de l’environnement.
```

## Management visuel
```
Représentation claire et partagée du travail, des priorités, des indicateurs et des blocages afin de faciliter la compréhension et les décisions collectives.
```

## Cycle Time
```
Temps écoulé entre le début effectif du traitement d’un élément et sa réalisation complète.
```

## Agilité
```
Culture de travail qui cherche à créer de la valeur dans l’incertitude grâce à des cycles courts, au feedback, à la collaboration et à l’adaptation continue.
```

## Developers
```
Membres de la Scrum Team qui organisent leur travail et mobilisent les compétences nécessaires pour produire à chaque Sprint un incrément de qualité.
```

## Lead Time
```
Délai total entre l’acceptation d’une demande et sa livraison au client, incluant le travail actif et les temps d’attente.
```

## Kaizen
```
Démarche d’amélioration continue fondée sur de petits changements réguliers, testés, observés puis ajustés collectivement.
```

## Scrum Master
```
Responsable de l’efficacité de la Scrum Team, qui aide l’équipe et l’organisation à comprendre Scrum, lever les obstacles et progresser.
```

## Complexité
```
Situation dans laquelle les nombreuses interactions rendent les résultats partiellement imprévisibles et imposent d’expérimenter plutôt que de tout anticiper.
```

## Product Owner
```
Responsable de la maximisation de la valeur du produit, de l’Objectif de Produit et de la gestion efficace du Product Backlog.
```

## Sprint Retrospective
```
Événement durant lequel la Scrum Team inspecte sa manière de travailler et choisit des améliorations concrètes à expérimenter dès le Sprint suivant.
```

## Empirisme
```
Principe selon lequel les décisions doivent s’appuyer sur l’expérience, les faits observables et l’apprentissage plutôt que sur la seule prédiction.
```

## Product Backlog
```
Liste émergente et ordonnée de tout ce qui pourrait être nécessaire pour améliorer le produit et atteindre l’Objectif de Produit.
```

## Approche prédictive
```
Mode de pilotage fondé sur l’analyse et la planification initiales, pertinent lorsque le besoin, la solution et l’environnement sont suffisamment stables.
```

## Kanban
```
Méthode de pilotage en flux continu qui visualise le travail, limite l’encours et améliore progressivement les délais et la fluidité.
```

## Definition of Done
```
Ensemble partagé de critères de qualité qu’un incrément doit respecter pour être considéré comme réellement terminé, utilisable et transparent.
```

## Daily Scrum
```
Événement quotidien de 15 minutes durant lequel les Developers inspectent leur progression vers l’Objectif de Sprint et adaptent leur plan.
```

## User Story
```
Formulation concise d’un besoin du point de vue de l’utilisateur, utilisée pour soutenir le dialogue, la priorisation et la validation.
```

## Approche adaptative
```
Mode de pilotage qui avance par expérimentations successives afin d’apprendre du réel et d’ajuster progressivement le produit, les priorités et le plan.
```

## Manifeste Agile
```
Texte fondateur publié en 2001 qui énonce quatre valeurs et douze principes privilégiant les interactions, la valeur, la collaboration et l’adaptation.
```

## Lean
```
Approche visant à maximiser la valeur pour le client en réduisant les gaspillages, les attentes et les inefficacités du système global.
```

## Feedback
```
Information obtenue en confrontant une hypothèse, un produit ou une pratique au réel afin de confirmer, corriger ou réorienter les décisions.
```
